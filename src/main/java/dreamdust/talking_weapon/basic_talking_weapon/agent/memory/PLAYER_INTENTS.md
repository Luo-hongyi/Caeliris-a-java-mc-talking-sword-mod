# Player Intent 枚举草案

本文档用于定义 **LTM 生成前的玩家意图层**。

它的目标不是直接生成长期记忆，而是先回答一个更基础的问题：

- 玩家最近这一段时间，**大概率正在做什么**

后续 episode 分割、LTM 生成触发、以及记忆总结的主题约束，都应建立在这层判断之上。

## 1. 设计目标

从游戏设计上，剑的长期记忆应当：

- 围绕 **玩家行为** 来组织
- 以 **共同旅程** 为主线，而不是机械记录环境片段
- 让环境信息只作为行为的背景、地点语义和氛围补充

因此这里的 `player intent` 层，核心作用是：

- 把连续的 STM 行为流解释成“阶段性目的”
- 在阶段性目的明显变化时，作为 episode 切分的主断点
- 给后续 LTM 总结器一个明确主题，避免一条记忆混入过多无关标签

## 2. 总体原则

### 2.1 玩家行为优先，环境语义辅助

intent 的判定应优先依赖：

- 玩家动作
- 玩家移动模式
- 玩家交互对象
- 玩家产出结果

环境信息只用于：

- 增强已有 intent 的置信度
- 区分同类动作在不同场景下的含义
- 帮助 LLM 在总结时补入地点、结构、群系、时间氛围

环境本身不应单独生成 intent。

例如：

- “在村庄附近”本身不是 `SOCIAL`
- “在工作台附近”本身不是 `CRAFT`
- “在建筑区域附近”本身不是 `BUILD`

必须先有对应行为，再由环境给予额外支持。

### 2.2 intent 是阶段性目的，不是单个动作标签

intent 不等于一次动作事件，而是对最近一个连续行为窗口的解释。

因此：

- `MINE_BLOCK` 不必然等于 `GATHER`
- `PLACE_BLOCK` 不必然等于 `BUILD`
- `USE_ITEM` 不必然等于 `GATHER`

要看它们在最近行为流中的组合、频率、产出和上下文。

### 2.3 断点优先由 intent 偏移触发

当前设计里，LTM 生成任务优先由以下事件触发：

- 最近行为统计显示玩家主导 intent 明显偏移

好处是：

- STM pool 可以保持连续
- 不需要在每个动作处生硬切块
- 真正触发 LTM 生成时，LLM 仍可在最近连续窗口里自行决定更合理的叙事截断点

兜底规则仍然保留：

- 若 STM pool 持续累积过长，即使 intent 没有明显偏移，也要触发一次生成

## 3. intent 枚举

当前先定义七类高层玩家意图：

- `GATHER`
- `TRAVEL`
- `EXPLORE`
- `COMBAT`
- `BUILD`
- `CRAFT`
- `SOCIAL`

它们是 **episode 分割层** 和 **LTM 主题层** 的枚举，不要求和底层 `ActionType` 一一对应。

## 4. 各 intent 的判定语义

### 4.1 `GATHER`

含义：

- 玩家正在有目的地获取资源、材料、掉落物或生产输入

核心证据：

- 挖掘方块
- 使用与收集行为直接相关的工具
- 获得资源性物品

辅助证据：

- 行为连续发生在资源区域
- 行为结果明显表现为材料累积
- 同一类采集行为在短时间内重复出现

特别说明：

- `USE_GATHER_TOOL` 应视为采集侧的主信号
- 若同一次有效采集同时产生了 `USE_GATHER_TOOL` 和 `MINE_BLOCK`，上层打分时应由 `USE_GATHER_TOOL` **覆盖** `MINE_BLOCK`，避免一次挖掘被双倍计分
- `MINE_BLOCK` 因此更适合作为“有挖掘发生”的补充证据，或在未命中 `USE_GATHER_TOOL` 时的弱替代证据
- 原因是部分资源获取并不表现为挖方块，但仍然是明确的采集行为
- 因此后续底层动作层需要区分“普通 use item”和“采集性 use tool”
- “获得了资源物品”是独立的结果证据，应单独由 `ACQUIRE_ITEM` 表达
- 当前 `ACQUIRE_ITEM` 只表达“玩家拾取了掉落物”，不再混入 crafting / smelting 结果进入
- 这类结果证据不负责反推出工具是否正确，它只回答“玩家有没有拿到东西”

不应直接作为反证的行为：

- 旅行过程中的少量挖掘
- 旅行过程中的少量垫脚放块

因为在 Minecraft 中，这些动作可能只是为了继续前进，而不是偏离 `TRAVEL`

### 4.2 `TRAVEL`

含义：

- 玩家正在进行真实位移，从一个区域前往另一个区域

核心证据：

- 基于锚点距离的持续位移
- 最近一段时间内明显离开上一个活动区
- 群系、结构、地形语义发生阶段性变化

辅助证据：

- 路途中出现少量清路、搭路、垫脚行为
- 玩家没有在某个局部区域内持续进行高密度生产/战斗/社交动作

特别说明：

- `TRAVEL` 的成立前提，不是“玩家一直在走”，而是“玩家确实跨越了足够距离”
- 当前这类 intent 应建立在“锚点位移”上，而不是局部绕圈
- 因此在已经确认真实旅行的前提下，不应因为 `MINE_BLOCK` 或 `PLACE_BLOCK` 就直接削弱 `TRAVEL`

环境加权建议：

- 新结构附近
- 新群系
- 跨维度

这些信息可以增强旅行阶段感，但不能脱离位移本身独立成立。

### 4.3 `EXPLORE`

含义：

- 玩家正在深入未知地点、结构或奖励点，并把“发现内容”转化为阶段性收获

核心证据：

- 打开仍挂着原生战利品表的容器

辅助证据：

- 行为前后伴随明显位移、群系变化或跨结构探索
- 行为发生在需要深入搜索的地点，而不是家中常规储物
- 同一时间段内伴随战斗，表现为“边探索边清路”

特别说明：

- `OPEN_LOOT_CONTAINER` 与普通开箱不同，它只表达“首次打开仍带 loot table 的战利品容器”
- 这使得 `EXPLORE` 可以与普通 `TRAVEL` 区分开：
  - `TRAVEL` 更偏向跨区域位移
  - `EXPLORE` 更偏向进入未知地点后的发现与搜刮

### 4.4 `COMBAT`

含义：

- 玩家正在主动参与战斗，或者持续应对威胁

核心证据：

- 攻击
- 击杀
- 受伤
- 死亡

辅助证据：

- 一段时间内反复出现战斗相关事件
- 周边威胁环境明显
- 当前并不呈现稳定旅行主导

额外加权建议：

- 当玩家不处于明显 `TRAVEL` 主导时，提高 `COMBAT` 置信度
- 当事件发生在结构附近时，可额外提高 `COMBAT` 置信度

这样可以帮助区分：

- “边走边顺手打一下”
- “正在清据点 / 守点 / 深入危险地点”

### 4.5 `BUILD`

含义：

- 玩家正在围绕一个相对稳定地点进行结构搭建、改造或整理

核心证据：

- 放置方块

辅助证据：

- 同一区域持续出现放置行为
- 同一区域出现一定规模的结构改造痕迹
- 当前位置接近已注册地点、基地或被识别的建设区域

额外加权建议：

- 当玩家并非明显 `TRAVEL` 主导时，提高 `BUILD` 置信度
- 当行为发生在注册地点或熟悉活动区附近时，提高 `BUILD` 置信度

边界提醒：

- 单次垫脚、封路、搭桥不必然是 `BUILD`
- `BUILD` 更强调“围绕一个局部空间持续塑形”

### 4.6 `CRAFT`

含义：

- 玩家正在通过工作站、功能方块或合成过程，进行制造、加工、整理和产出转换

命名约定：

- 这一类 intent 统一命名为 `CRAFT`
- 不再使用 `CREATE`

核心证据：

- 与功能方块交互
- 合成行为

辅助证据：

- 制造链路连续出现
- 输入材料被消费并转化为更高阶产物
- 玩家停留在工作区并持续进行处理类行为

实现层提醒：

- 当前动作层对这类行为的表达还不够细
- 后续应优先补入“功能方块交互”和“合成检测”相关动作
- `CRAFT` 当前不再使用 `ACQUIRE_ITEM` 作为结果证据
- 原因是 `ACQUIRE_ITEM` 已收口为“拾取掉落物”，不再代表生产链产出进入

### 4.7 `SOCIAL`

含义：

- 玩家正在与 NPC、村民或其他明确的社交对象进行互动

核心证据：

- 与村民 / NPC 交互
- 交易

辅助证据：

- 同一社交对象被持续交互
- 行为发生在村庄或其他社交场景中

边界提醒：

- 仅仅靠近村庄不代表 `SOCIAL`
- 只有在“真实交互”发生时，社交 intent 才应成立

## 5. 建议补充的底层证据动作

当前 `ActionType` 对 LTM 生成来说仍然偏粗。

为了更稳定地支持上述 intent，后续建议补充或细化以下证据动作：

- `USE_GATHER_TOOL`
- `ACQUIRE_ITEM`
- `INTERACT_FUNCTION_BLOCK`
- `OPEN_LOOT_CONTAINER`
- `CRAFT_ITEM`
- `INTERACT_NPC`

这些动作不是为了把系统做复杂，而是为了避免高层 intent 只能依赖过于含糊的底层信号。

特别是：

- `USE_ITEM` 目前过宽，无法区分“采集性工具使用”和普通使用
- 泛化 `INTERACT` 目前过宽，无法区分社交交互和功能方块交互

## 6. 与 episode 分割的关系

当前建议的 episode 分割主流程是：

1. 对最近一段 STM 行为做 intent 统计
2. 推断当前主导 intent
3. 当主导 intent 发生明显偏移时，触发一次 LTM 生成任务
4. 由 LLM 在该连续窗口中决定更合理的记忆截断位置
5. 若 STM 长度超出上限，则触发兜底切分

这意味着：

- intent 层负责“什么时候该结算”
- LLM 负责“这一段旅程该如何叙述”

## 7. 当前结论

当前版本的 `player intent` 设计，先以这七类为主：

- `GATHER`
- `TRAVEL`
- `EXPLORE`
- `COMBAT`
- `BUILD`
- `CRAFT`
- `SOCIAL`

其中最重要的几条边界是：

- `GATHER` 应把“采集性工具使用”视为强证据
- `TRAVEL` 一旦确认真实位移，不应因少量挖掘/放块被轻易打断
- `CRAFT` 应独立于 `BUILD`，并明确覆盖功能方块交互与合成
- 环境只能增强 intent，不能替代行为本身

这份文档的作用是先固定设计语义。

下一步再基于它落地：

- `PlayerIntent` 枚举
- 底层证据动作扩容
- intent 统计窗口
- intent 偏移触发规则
